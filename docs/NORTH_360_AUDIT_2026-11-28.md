## Architecture mapped

`NORTH`'s declared `playbooks.yml` list contains 21 stages. Network/owner preflights and Vagrant guest creation precede Ansible. The sequence joins parent/child AD, members, root/member W32Time, accounts, WS01 foundation, ACLs, MSSQL/IIS/security, `kingdoms-health.yml`, vulnerabilities and Phase 01, then seeds the 20 Windows LPE techniques via `ws01-lpe-install.yml` and runs `kingdoms-health-final.yml`.

`goad/provider/vagrant/vmware_kingdoms.py::finalize_install()` enforces pre-isolation guest-control health and delegates to `goad/provider/vagrant/vmware_nomad.py::finalize_install()`, which only transitions into `exercise`. `validate-north-runtime.sh` is a **separate** acceptance path after the instance is installed. There is no confirmed final post-isolation AD trust proof in the install finalizer itself.

## Positive controls retained

- VMware inventory, MAC and vmnet ownership checks; foreign NAT-forward and other-lab protection; NORTH-only five-VM scope.
- Explicit parent/child AD layout and domain-specific NTP source.
- 21-play NORTH manifest and 20-technique LPE source catalog.
- Post-isolation read-only runtime validator and the ability to preserve the installed instance.
- No automatic machine password reset, domain rejoin, unconstrained route re-enable or arbitrary attacker action in the release acceptance scripts.

## Recommended acceptance sequence

1. **Source gate:** merge-free branch update, `bash -n`, targeted pytest, then `bash scripts/validate-course1.sh --skip-host`. The one-shot runner now repeats this full source gate **before contacting any VM**; Phase 04's nested owner gate uses the same interpreter. Check GitHub's dedicated NORTH CI result.
2. **Runtime gate:** `./goad.sh -t validate -l NORTH -p vmware -i 34a864-north-vmware`; exercise mode must remain intact.
3. **Curriculum gate:** use `bash scripts/validate-north-all.sh 34a864-north-vmware --confirm-transient-right --rdp-mode legacy` for the *currently installed legacy* RDP bot. Do not misrepresent that result as headless-RDP acceptance. If moving to headless, separately prove the Robb service/session, explicitly disable only the original DC02 `connect_bot`, then rerun `--rdp-mode headless`.
4. **Functional attack gate:** use controlled, reversible end-to-end Phase 03 and a Rickon-to-SYSTEM demonstration with evidence, not just status markers. This is not part of the one-shot read-only smoke suite.
5. **Fresh-install gate:** independently test a clean NORTH installation **only after** the above source/runtime gaps are closed. Fail the install if post-isolation trust is unhealthy, without secretly repairing accounts or weakening lab vulnerabilities.
